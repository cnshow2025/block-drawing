# 方塊填色 Block Drawing

把繽紛方塊拖進畫框的填充拼圖遊戲。純 HTML + CSS + JavaScript，沒有建置流程、沒有外部依賴，
用瀏覽器直接開 `index.html` 就能玩，手機與桌機都支援。

## 玩法

- **拖曳**方塊盤裡的方塊放進畫框，方塊會自動吸附到格線上。
- 放下前會出現**落點預覽**：綠色代表可以放，紅色代表卡到東西。
- 點一下方塊**選取**，**再點一下就轉 90°**，連續點就一直轉；也可以按「旋轉」「翻轉」按鈕，拖曳途中也能按。
- 已經放進畫框的方塊同樣可以點著轉，會以自己的中心原地旋轉；旁邊空間不夠時就轉不動，得先把它拖開。
- 放錯了可以把方塊**從畫框裡拖回來**，或按「復原」。
- 鍵盤快捷鍵：<kbd>R</kbd> 旋轉、<kbd>F</kbd> 翻轉、<kbd>Ctrl</kbd>+<kbd>Z</kbd> 復原、<kbd>Esc</kbd> 取消。

### 兩種關卡模式

| 模式 | 出現在 | 過關條件 | 星等怎麼算 |
| --- | --- | --- | --- |
| **精準拼合** | 三十道主線關卡 | 用完所有方塊、畫框 100% 填滿 | 不用提示三顆星，用一次兩顆星，用更多一顆星 |
| **填滿計分** | 每日挑戰 | 填滿率跨過一星門檻 | 依填滿率跨過三道門檻，使用提示會扣減 |

主線三十關全部都要**剛好填滿**——方塊不多不少，切割生成保證有解。
填滿率計分只留給每日挑戰，因為每日的題目是臨時生成的，方塊本來就不會剛好。

| 4 碎片星河 | 五格 | pentomino 十二件 | 十字、菱形、階梯、環形 |

### 難度是怎麼調的

`tools/difficulty.js` 會模擬玩家：拿方塊盤（順序已洗過、方向全歸零）用樸素回溯法重解一次，
數需要回溯幾個節點。節點越多代表死路越多、越需要想，對人來說就越難。

同一個畫框配同一個形狀池，**換個種子就會切出難度差好幾個數量級的題目**，
所以每一關的 `seed` 都是掃描上百個候選後挑出來的——挑落在該關目標難度帶裡的那一個。
世界 3 尾聲到世界 5 的節點數是 915 → 1,670 → 2,694 → 4,689 → 7,951 →
12,773 → 13,411 → 23,534 → 28,839 → 41,092 → 80,284，嚴格遞增。

## 進度與成績

進度存在**這台裝置的瀏覽器**裡（`localStorage`），關掉分頁、重開瀏覽器、關機再開都還在，
不需要註冊也不會上傳到任何地方。

- 第一次進來會問一次名字，之後顯示在標題頁與成績頁，隨時可以在成績頁改
- 標題頁的**繼續遊戲**直接跳到「第一關還沒通關的關卡」，已經打過的不會重來
- **我的成績**頁有三塊：總覽（總星數、完成關卡數、三星關卡數、平均填滿率、每日連續天數）、
  三十關的逐關明細（星數／最佳填滿率／狀態）、最近 14 天的每日挑戰紀錄
- **所有關卡隨時都能直接點進去玩**，不需要照順序解鎖；關卡選單會在你進度接續的那一關標上「接著打」
- 關卡選單底部的「清除進度」會刪掉所有紀錄，但不會刪掉名字

換一台電腦或換一個瀏覽器就是另一份進度——資料存在本機，不會跟著帳號走。

## 圖片拼圖模式

遊戲畫面右上角有一顆寫著「圖片 開／關」的按鈕，三十關**每一關**都能隨時切換。
**預設是關的**——想玩才開，關卡內容完全不變，只是外觀不同。

**方塊從在方塊盤裡就帶著自己「正確位置」的那片圖案**，靠紋路接不接得起來找位置；
轉動方塊時圖案跟著轉。等放上去才顯示圖對解題毫無幫助，所以不那樣做。

六張圖全部是 `js/pictures.js` 用 Canvas **程式畫出來的**，倉庫裡沒有任何圖檔：
花磚、樹葉、魚鱗、花布、拼貼、星圖。

選圖案的重點**不是紋理要密，而是不同區域的色調要分得開**。

一開始做錯方向：把圖畫成密密麻麻的小花樣，局部很忙，但每一區看起來都差不多，
碎片拿在手上還是認不出自己該去哪。後來寫了個量尺（把圖切成一格大小的方塊，
量每塊跟「色調最接近的另一塊」差多少），才看清楚問題有多大——舊版的樹葉
**56 格裡有 55 格色調幾乎完全相同**。

現在的做法是疊一層大範圍的色彩場：色相沿著寬度掃過一段色域、明度沿著高度由暗
走到亮，兩個方向都單調（不用波紋，波紋會讓不同位置折回同一個色相），每一格就
落在自己獨有的色調座標上。掃描寬度是取捨——窄一點各張圖的性格明顯，寬一點碎片
才好認；實測窄到 130 度時有三分之二的格子撞色，所以定在 200 度上下，
而且每張圖從不同的色相起點出發，才不會六張全變成同一條彩虹。

量下來色調差距的中位數從 3.9 提升到 16.6，色調幾乎相同的格數從 317 降到 64。

畫布依畫框的長寬比產生，圖案不會被拉變形。

只有精準拼合的關卡能開：方塊盤就是切割結果本身，每一塊都查得到自己的正確位置
（`Board.assignHomes` 做一對一配對）。三十關主線全是精準拼合，所以每一關都能開；
每日挑戰是填滿率計分、方塊不見得剛好，沒有「正確位置」可言，所以不開放。

還有一個額外的看點：切割出來的解法往往不只一種，所以拼滿了也可能圖案沒接上。
結算畫面會告訴你這次的圖案有沒有完全對上（`Board.allAtHome`）。

## 每日挑戰

每天一題，**題目由當天日期決定**，所以同一天進來永遠是同一題、全世界也是同一題，隔天自動換。

- 畫框從 16 個每日專用的輪廓裡抽，抽哪個、抽幾塊方塊、抽掉幾塊補幾塊，全由日期的種子決定
- **星期一到三**用四格＋五格方塊，**星期四到日**用五格＋六格，週末難一點
- 一律是填滿計分模式，星等門檻**由程式當場估算**（見下），不需要人工校準
- 會記錄連續挑戰天數，但每日挑戰的星星不計入主線的收集進度

### 星等門檻怎麼訂

每日的題目是臨時生成的，沒辦法先人工試玩校準，所以程式自己算：

用「最佳貼合」啟發式跑 200 輪隨機重啟，取這 200 局成績的**第 90 百分位**當作基準。
不取最高分是因為那可能是兩百次裡的一次僥倖——真填得出來，但對真人幾乎等於不存在；
第 90 百分位代表「打得不錯的一局」，跨種子也穩定得多。三道門檻分別是基準的 76%、88%、100%
（無條件捨去，四捨五入會把門檻推到可達值之上）。

`tools/validate-daily.js` 會模擬未來 N 天，確認每天都生得出題、門檻遞增，
而且用另一組種子跑更強的獨立搜尋（400 輪）確實搆得到三星門檻。

## 關卡是怎麼出的

與其「出題之後再想辦法解」，這個遊戲反過來做：**先把空畫框完整切成碎片**。

1. 拿關卡的畫框輪廓，用回溯法把可填區完整切成該世界形狀池裡的形狀。
2. 切出來的碎片就是玩家手上的方塊盤——所以精準拼合模式**必定有解**。
3. 切割由關卡表裡的固定種子驅動，同一關每次進入都是同一題。
4. 計分模式再從這組碎片抽掉幾塊、補進幾塊隨機形狀，讓完美填滿幾乎不可能，改以填滿率論高下。

回溯時有兩道剪枝讓它跑得很快：每塊連通空白區的格數必須 ≥ 最小形狀，而且必須能由形狀池的尺寸組合出來。
三十關全部生成完不到一秒。

## 專案結構

```
index.html              單一入口
css/style.css           主題色、版面、動畫
js/shapes.js            形狀資料庫與旋轉／鏡像變換
js/generator.js         種子亂數、畫框解析、反向切割、填滿率估算
js/levels.js            五個世界三十關的資料
js/pictures.js          圖片拼圖的六張圖（Canvas 現畫，倉庫裡沒有圖檔）
js/board.js             棋盤模型、放置驗證、填滿率、星等、提示
js/storage.js           localStorage 進度存檔
js/audio.js             WebAudio 即時合成音效（不需音檔）
js/render.js            把遊戲狀態畫成 DOM
js/input.js             Pointer Events 拖曳、旋轉、翻轉
js/game.js              主流程：畫面切換、關卡選單、結算
tools/validate-levels.js  關卡驗證腳本
tools/validate-daily.js   每日挑戰驗證腳本
tools/difficulty.js       難度量尺（模擬玩家重解，數回溯節點）
```

## 開發

沒有安裝步驟。要本機跑起來：

```bash
python3 -m http.server 8000     # 或任何靜態伺服器
# 開 http://localhost:8000
```

改了關卡資料之後，跑驗證腳本確認每一關都還切得出來：

```bash
node tools/validate-levels.js       # 三十道固定關卡
node tools/validate-daily.js 365    # 模擬未來 365 天的每日挑戰
node tools/difficulty.js            # 量每一關的難度，確認曲線是遞增的
```

它會列出每關的格數、塊數與實際用到的種子；計分關卡還會用「最佳貼合」啟發式估算可達的最高填滿率，
用來校準星等門檻。
